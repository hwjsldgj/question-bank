# Requirements Document

Feature Name: question-paper-generator
Updated: 2026-10-03

## Introduction

本系统（以下简称"系统"）是一个面向教师与培训人员的**桌面端自动出题与组卷工具**。系统以本地题库为基础数据源：出题者在应用内**手工录入或批量粘贴**题目，题目分为**选择题（单选、多选）**与**解答题**两类；AI 通过 **API 调用**在入库时自动分析难度（易/中/难）。组卷时，出题者选择需要输出的部分（**选择题部分与解答题部分均可选，可只选其一或同时选择**），并指定科目、难度、题型与数量。选题由**算法评分决策**驱动——综合难度匹配度、知识点覆盖、使用频次惩罚、最近使用时间惩罚与人工质量标记计算选题评分，再进行**加权随机抽样**，以尽量降低最近被选用题目再次出现的概率。当候选题数量不足时，由 **AI 通过 API 依据知识点补题**。最终导出**按「选择题 / 解答题」两部分分区、含每题分值与总分、卷末附答案页的 TXT 或 PDF 试卷**。

系统遵循三条核心原则：
1. **题库优先、AI 兜底**：题目优先来自题库，AI 仅在数量不足时介入。
2. **评分决策、加权随机**：避免纯排序的机械感，也避免纯随机的低质量，兼顾问卷质量与多样性，并抑制近期重复。
3. **本地桌面运行**：题库、组卷历史、使用记录与配置均保存在本机，无需服务器与账号体系。

范围说明（本期不做）：
- 用户导入 Excel/Word/PDF 题库文件（题库仅通过系统内手工录入与批量粘贴建立）
- 在线答题与自动判分（解答题仅提供参考答案与解析，不自动判分）
- 判断题与填空题（选择题部分仅含单项选择、多项选择）
- 多用户账号体系与权限（本期按单用户设计）

## Glossary

- **系统 (System)**：本自动出题与组卷工具。
- **题库 (Question Bank)**：系统中所有题目的集合，是组卷的首选来源。
- **题目 (Question)**：一道题，包含科目、知识点、题型、题干、选项（仅选择题）、答案、难度、来源标记与使用记录。
- **选择题 (Choice Question)**：含选项的客观题，分为单项选择与多项选择。
- **解答题 (Solution Question)**：需要书写解答过程的主观题，题干不含选项，包含参考答案与解析。
- **科目 (Subject)**：题目的归属分类，用于组卷筛选的一级维度。
- **知识点 (Knowledge Point)**：题目关联的知识单元，用于选题覆盖度计算与 AI 补题生成。
- **题型 (Question Type)**：取值为"单选题 / 多选题 / 解答题"。
- **题组部分 (Paper Section)**：试卷的两大组成部分，取值为"选择题部分 / 解答题部分"。
- **难度 (Difficulty)**：题目难易程度，取值为"易 / 中 / 难"三级。
- **组卷条件 (Paper Criteria)**：用户为生成试卷指定的筛选约束，包含启用的部分、科目、难度、题型与数量。
- **命中题 (Matched Question)**：题库中满足某个题型组卷条件的题目。
- **选题评分 (Selection Score)**：对候选题计算的综合分值，用于决定选取倾向。
- **加权随机抽样 (Weighted Random Sampling)**：以选题评分为权重进行不放回随机抽取。
- **冷却窗口 (Cooldown Window)**：题目最近被选用后的抑制期，窗口内题目被额外降权。
- **使用记录 (Usage Record)**：题目被选入试卷的次数与最近使用时间。
- **AI 补题 (AI Supplement)**：当候选题数量不足时，由 AI 通过 API 依据知识点生成的新题目。
- **AI 生成题 (AI-Generated Question)**：由 AI 补题产生并入库的题目，带来源标记。
- **试卷 (Paper)**：按"选择题 / 解答题"两部分组织、含每题分值与总分的题目集合。
- **答案页 (Answer Sheet)**：附于试卷文档末尾，按题型分区列出各题正确答案与解析的独立分区。
- **组卷任务 (Generation Task)**：一次组卷请求及其结果的记录。

> 术语约定：本文件中"应"等价于 EARS 模板中的 "SHALL"。

## Requirements

### Requirement 1：题目手工录入与维护

**User Story:** AS 出题者, I want 在系统内新建、编辑、删除题目, so that 我能可持续地维护专属题库。

#### Acceptance Criteria

1. WHEN 出题者提交一道包含科目、知识点、题型、题干与答案的题目, 系统应保存该题目并为其分配唯一标识。
2. WHEN 出题者提交的题目缺少任一必填字段, 系统应拒绝保存并指明缺失字段。
3. WHEN 出题者对已有题目执行编辑并提交, 系统应更新该题目的内容并保留其唯一标识与历史使用记录。
4. WHEN 出题者对已有题目执行删除, 系统应从题库中移除该题目并使其不再参与后续组卷。
5. WHERE 题型为"解答题", 系统应要求题目包含参考答案字段。

### Requirement 2：批量粘贴录入

**User Story:** AS 出题者, I want 一次性粘贴多道题目文本, so that 我能快速建库而无需逐题录入。

#### Acceptance Criteria

1. WHEN 出题者粘贴包含多道题目的文本并触发解析, 系统应按题目分隔规则将其拆分为多道候选题目。
2. WHEN 系统完成粘贴文本解析, 系统应展示候选题目的结构化预览供出题者确认。
3. WHEN 出题者确认候选题目的预览结果, 系统应将确认后的题目批量写入题库。
4. IF 某条候选题目无法解析出必填字段, 系统应标记该条为"待修正"并在预览中突出显示。
5. WHERE 候选题目被识别为"解答题", 系统应要求其包含参考答案字段。

### Requirement 3：题型规则与答案校验

**User Story:** AS 出题者, I want 系统按题型规则校验题目结构, so that 入库题目格式统一且可用。

#### Acceptance Criteria

1. WHERE 题型为"单选题", 系统应要求 2 个及以上选项且答案恰为 1 个选项。
2. WHERE 题型为"多选题", 系统应要求 2 个及以上选项且答案为 1 个及以上选项。
3. WHERE 题型为"解答题", 系统应要求题目不包含选项且包含参考答案。
4. WHERE 题型为"解答题", 系统应允许包含解析字段。
5. IF 题目的答案与所选题型的规则不一致, 系统应拒绝保存并说明不一致原因。

### Requirement 4：AI 难度分析（API 调用）

**User Story:** AS 出题者, I want 题目入库时由 AI 通过 API 自动标注难度, so that 我无需逐题人工判断难度。

#### Acceptance Criteria

1. WHEN 一道题目保存成功, 系统应通过 AI API 调用分析该题目的难度并标注为"易""中""难"之一。
2. WHEN 系统完成难度分析, 系统应记录该难度的来源为"AI"。
3. IF AI API 调用失败、超时或返回无效结果, 系统应将题目难度置为"待确认"并允许出题者后续手动设置。
4. IF 出题者在难度分析完成前手动设置了难度, 系统应保留该人工设置的难度并不再被 AI 结果覆盖。
5. WHEN 系统调用 AI API 进行难度分析, 系统应遵守所配置的请求超时与重试次数。

### Requirement 5：难度、标签与质量人工修正

**User Story:** AS 出题者, I want 手动修正题目的难度、标签与质量标记, so that 我对题目质量保有最终控制权。

#### Acceptance Criteria

1. WHEN 出题者修改某题目的难度, 系统应保存新难度并记录其来源为"人工"。
2. WHEN 出题者修改某题目的科目或知识点, 系统应保存新标签并用于后续组卷筛选。
3. WHEN 出题者标记某题目的质量等级, 系统应保存该质量标记并用于后续选题评分。
4. WHILE 某题目的难度来源为"人工", 系统应在后续 AI 分析中保持该难度不变。

### Requirement 6：题库检索与可用量统计

**User Story:** AS 出题者, I want 按条件查看题库与可用题量, so that 我能在组卷前了解题目是否充足。

#### Acceptance Criteria

1. WHEN 出题者按科目、知识点、难度、题型中的一个或多个条件进行检索, 系统应返回匹配的题目列表。
2. WHEN 出题者设定一组组卷条件, 系统应显示满足全部条件的命中题数量。
3. WHEN 出题者调整组卷条件, 系统应实时更新命中题数量。
4. WHEN 出题者查看题目列表或题目详情, 系统应展示每道题目的历史使用次数与最近使用时间。

### Requirement 7：组卷条件配置

**User Story:** AS 出题者, I want 分别配置选择题部分与解答题部分的出题要求, so that 我能按需出卷。

#### Acceptance Criteria

1. WHEN 出题者配置组卷条件, 系统应允许其分别启用或停用"选择题部分"与"解答题部分"。
2. WHEN 出题者启用"选择题部分", 系统应允许其分别指定单项选择与多项选择的科目、难度与数量。
3. WHEN 出题者启用"解答题部分", 系统应允许其指定解答题的科目、难度与数量。
4. IF 出题者提交的组卷条件中所有部分均被停用, 系统应拒绝该请求并提示至少启用一个部分。
5. IF 出题者指定的任一数量非正整数, 系统应拒绝该请求并指明无效项。

### Requirement 8：候选题目评分决策

**User Story:** AS 出题者, I want 系统按综合评分决定选题倾向, so that 选出的题目兼顾难度、覆盖度与新鲜度。

#### Acceptance Criteria

1. WHEN 系统处理某一题型的选题需求, 系统应筛选满足该题型组卷条件（科目、难度、题型）的全部命中题作为候选集合。
2. WHEN 系统计算候选题的选题评分, 系统应综合难度匹配度、知识点覆盖、使用频次惩罚、最近使用时间惩罚与人工质量标记。
3. WHEN 系统计算候选题的难度匹配度, 系统应使难度与目标难度越接近的题目得分越高。
4. WHILE 候选集合中存在覆盖了当前试卷尚未覆盖知识点的题目, 系统应提高该题目的知识点覆盖得分。
5. WHEN 系统计算候选题的最近使用时间惩罚, 系统应按该题目距上次使用的时间间隔赋予惩罚，间隔越短惩罚越大。
6. WHEN 系统计算候选题的使用频次惩罚, 系统应按该题目的历史被选次数赋予惩罚，次数越多惩罚越大。
7. WHEN 出题者调整评分因子的权重, 系统应将新权重应用于后续的选题评分。
8. WHEN 出题者标记某题目为低质量, 系统应在选题评分中降低该题目的得分。

### Requirement 9：加权随机选组与同卷去重

**User Story:** AS 出题者, I want 在评分基础上随机抽题, so that 试卷质量有保障且不呆板。

#### Acceptance Criteria

1. WHEN 系统完成候选题的评分, 系统应以其选题评分为权重对候选集合执行不放回加权随机抽样。
2. WHEN 系统抽取题目, 系统应在同一份试卷内避免重复选取同一题目。
3. WHEN 系统从候选集合抽中一道题目, 系统应在继续抽样前将已抽中题目移出候选集合。
4. WHEN 系统完成某一题型的选组, 系统应记录每道入选题目的来源为"题库"。

### Requirement 10：库优先与 AI 补题生成

**User Story:** AS 出题者, I want 题库不足时由 AI 补齐, so that 我仍能拿到满足数量要求的试卷。

#### Acceptance Criteria

1. WHEN 某题型的候选题数量大于或等于所请求数量, 系统应仅从候选集合中选组且不触发 AI 补题。
2. IF 某题型的候选题数量少于所请求数量, 系统应计算差额并将差额部分交由 AI 通过 API 依据该科目与知识点生成。
3. WHEN AI 依据知识点生成题目, 系统应按所请求的题型与难度生成对应题目。
4. WHEN 系统生成 AI 补题, 系统应校验生成题目符合 Requirement 3 的题型规则；不符合的生成题目应被丢弃并重新生成。
5. WHEN 系统生成 AI 补题, 系统应将生成的题目写入题库并标记其来源为"AI 生成"。
6. IF AI 补题在重试后仍无法满足差额数量, 系统应向出题者报告实际可提供的数量并请求确认。

### Requirement 11：分值与总分设置

**User Story:** AS 出题者, I want 为题型或题目设置分值, so that 试卷能自动汇总总分。

#### Acceptance Criteria

1. WHEN 系统生成一份试卷, 系统应允许出题者按题型设置统一分值或为单道题目单独设置分值。
2. WHEN 出题者设置分值, 系统应按"分值 = 数量 × 单题分值"计算各题型小计。
3. WHEN 出题者完成分值设置, 系统应汇总并显示试卷总分。
4. IF 存在未设置分值的题目, 系统应在导出前提示并阻止导出。

### Requirement 12：试卷导出

**User Story:** AS 出题者, I want 导出分两部分的试卷文档, so that 我能直接打印或在线分发。

#### Acceptance Criteria

1. WHEN 出题者触发试卷导出, 系统应生成包含题干与选项（仅选择题）的试卷文档。
2. WHEN 系统排版试卷文档, 系统应将其分为"选择题"与"解答题"两部分；某部分未被启用时该部分不出现。
3. WHEN 系统排版选择题部分, 系统应进一步按"单项选择""多项选择"分大题排布。
4. WHEN 系统排版试卷文档, 系统应在各分区标题处标注该分区的题目数量与分值小计。
5. WHEN 系统排版试卷文档, 系统应在文档中标明试卷总分。
6. WHEN 系统排版试卷文档, 系统应在文档末尾附上独立的答案页，按题型分区列出各题正确答案；解答题的答案应包含参考答案与解析。
7. WHEN 出题者选择导出格式, 系统应支持导出为 TXT 或 PDF 格式。
8. WHEN 系统完成导出, 系统应保存该试卷对应的组卷条件与导出记录以便复用。

### Requirement 13：使用记录与近期重复抑制

**User Story:** AS 出题者, I want 最近用过的题目尽量不重复出现, so that 试卷保持新鲜。

#### Acceptance Criteria

1. WHEN 系统将一道题目选入试卷, 系统应将该题目的使用次数加一，并将最近使用时间更新为本次组卷时间。
2. WHEN 系统计算候选题评分, 系统应对"最近使用时间"落在冷却窗口内的题目施加额外惩罚。
3. IF 冷却窗口内的可用题量不足以满足所请求数量, 系统应降低惩罚强度以从窗口内题目补足数量。
4. WHEN 出题者调整冷却窗口的长度, 系统应将新窗口应用于后续的选题评分。
5. WHEN 出题者查看题目详情, 系统应展示该题目的使用次数与最近使用时间。

### Requirement 14：组卷历史与配置复用

**User Story:** AS 出题者, I want 查看历史组卷并复用其配置, so that 我能快速重新出题。

#### Acceptance Criteria

1. WHEN 系统完成一次组卷任务, 系统应保存该任务的组卷条件、题目清单与导出记录。
2. WHEN 出题者查看历史组卷列表, 系统应展示各任务的创建时间、组卷条件与总分。
3. WHEN 出题者选择复用某个历史组卷任务, 系统应以该任务的条件填充组卷表单。
4. WHILE 出题者复用历史组卷任务, 系统应按当前题库重新选组题目并允许产生与历史不同的题单。

### Requirement 15（非功能）：AI 服务 API 配置

**User Story:** AS 出题者, I want 自行配置 AI 服务 API, so that 系统能通过 API 调用完成难度分析与补题。

#### Acceptance Criteria

1. WHEN 出题者提供 AI 服务的 API 接口地址、API Key 与模型名称, 系统应保存该配置并用于难度分析与补题。
2. IF 未配置有效的 AI 服务, 系统应在难度分析与补题功能处提示未配置，并保持手工录入与库内组卷可用。
3. WHEN 出题者更新 AI 服务配置, 系统应使用新配置执行后续的 AI API 调用。
4. WHEN 系统调用 AI API, 系统应设置请求超时与失败重试。
5. WHEN 出题者设置 AI API 的请求超时与重试次数, 系统应将新设置应用于后续调用。

### Requirement 16（非功能）：数据持久化与一致性

**User Story:** AS 出题者, I want 题库与组卷数据可靠保存, so that 我的工作不会丢失。

#### Acceptance Criteria

1. WHEN 系统完成任一对题库、使用记录或组卷数据的写操作, 系统应将其持久化到本机存储介质。
2. WHEN 系统在组卷过程中发生中断, 系统应保证题库中已有的题目与使用记录不发生损坏或丢失。
3. WHILE 系统处于运行状态, 系统应保证同一题目的并发编辑以最后一次提交为准。

### Requirement 17（非功能）：响应性能

**User Story:** AS 出题者, I want 系统快速响应, so that 出题流程顺畅。

#### Acceptance Criteria

1. WHEN 出题者对题库执行检索或命中量统计, 系统应在 2 秒内返回结果。
2. WHEN 出题者基于题库足量的条件发起组卷, 系统应在 5 秒内完成组卷与评分选组。
3. WHEN 系统触发 AI 难度分析或 AI 补题, 系统应向出题者展示进行中状态直至完成。

### Requirement 18（非功能）：桌面本地运行与数据存储

**User Story:** AS 出题者, I want 系统作为桌面程序在本地运行, so that 我的题库与试卷数据保存在本机且无需部署服务器。

#### Acceptance Criteria

1. WHEN 出题者在本机启动系统, 系统应作为桌面应用运行且无需外部服务器即可使用题库管理与库内组卷功能。
2. WHEN 系统读写题库、使用记录、组卷与配置数据, 系统应将数据存储于本机存储介质。
3. WHEN 系统执行导出, 系统应将生成的 TXT 或 PDF 文件保存到出题者指定的本机目录。
4. IF 本机缺少导出所选格式所需的运行环境, 系统应在导出前提示并给出可执行的替代格式。

## Confirmed Decisions（已确认决策）

| 决策项 | 结论 |
|--------|------|
| 出题机制 | 题库优先；评分决策后加权随机抽样；不足时 AI API 补题 |
| 交付形态 | 导出试卷文档（TXT / PDF） |
| 运行平台 | 桌面应用，本地存储 |
| 试卷结构 | 选择题部分 + 解答题部分（均可选，可单选其一或同时） |
| 选择题子类型 | 单项选择、多项选择 |
| 解答题 | 含参考答案与解析 |
| 题库来源 | 系统内手工录入 + 批量粘贴（不含文件导入） |
| 试卷组成 | 按部分/题型分区 + 每题分值 + 总分 |
| 答案处理 | 卷末附独立答案页 |
| 难度体系 | 三级（易/中/难） |
| AI 接入 | API 调用 |
| 选题算法 | 评分决策（难度匹配 / 知识点覆盖 / 使用频次 / 最近使用 / 人工质量）+ 加权随机抽样 |
| 重复抑制 | 使用记录 + 冷却窗口降权 |
| 随机与可复现 | 每次组卷随机选题，不要求可复现；历史仅复用配置 |
